# 03 · Running JS9

Five ways to run, from zero-setup to a full server install. Pick by what you're working
on. None of these require a build first — the bundles, wasm, and `node_modules` are all
committed.

| # | Path | Backend? | Use when |
|---|---|---|---|
| 1 | Open `js9.html` in a browser | no | Frontend-only work; quickest loop |
| 2 | `npm start` / `build/quicktest` | yes (Node helper) | Canonical local smoke run |
| 3 | `node js9Helper.js` | yes | Working on the backend itself |
| 4 | `./js9 -a` (Electron) | optional | Desktop app / `--hostfs` work |
| 5 | `./configure … && make install` | yes | Real web deployment |

---

## 1. Static frontend — just open the page

No server. The committed bundles + wasm are a complete app.

```bash
open js9.html          # macOS
# or drag js9.html onto a browser window, or serve the dir:
python3 -m http.server 8000   # then visit http://localhost:8000/js9.html
```

Then drag a FITS file onto the display, or pass one by URL:
```
http://localhost:8000/js9.html?url=https://hea-www.cfa.harvard.edu/~eric/coma.fits.gz&colormap=cool
```

Caveats:
- A `file://` URL works for most things, but **WebAssembly + workers prefer `http://`** —
  prefer `python3 -m http.server` over a raw `file://` open if the image won't load.
- Chrome over `file://` needs `--allow-file-access-from-files` (per the main README).
- Server-side analysis tasks are unavailable without the helper (path 2/3).

## 2. `npm start` — frontend + Node helper + browser (the canonical run)

[package.json](../package.json) wires npm to [build/quicktest](../build/quicktest):

```bash
npm start     # == build/quicktest
npm test      # == build/quicktest build/i800400.fits.gz  (also loads a test image)
```

What `quicktest` does:
1. `pgrep -f js9Helper.js || build/nnode` — start the helper if it isn't running
   (`build/nnode` kills any stale instance, then `node js9Helper.js`, logging to
   `~/logs/js9node.log` or `./js9node.log`).
2. `./js9 -v -b &` — open `js9.html` in a browser via the JS9 CLI.
3. If a FITS file was given: `./js9load <file>`, then `SetScale log`, `SetColormap
   viridis`, `DisplayPlugin JS9Magnifier`.

> ⚠️ The script prints a warning: **if Chrome is your default browser, quit Chrome
> first** so it can relaunch with the switches JS9 needs. Set `JS9_BROWSER`
> (`chrome|firefox|safari`) to choose.

This is the fastest way to exercise the full stack locally.

## 3. Backend only — run the Node helper directly

When you're editing `js9Helper.js`, the analysis plugins/wrappers, or debugging the
socket protocol:

```bash
node js9Helper.js
# backgrounded, with a log, the way the README suggests:
node js9Helper.js 1>~/logs/js9node.log 2>&1 &
```

- Listens on **port 2718**, all interfaces (`helperHost: "0.0.0.0"`). Override in
  [js9Prefs.json](../js9Prefs.json) (`helperPort`) or the `globalOpts` block in
  `js9Helper.js`.
- Per-client scratch dirs are created under `./tmp` (`workDir` in prefs). Create it if
  missing: `mkdir -p tmp`. They're auto-removed ~15 s after a client disconnects.
- For HTTPS, provide key/cert in `js9Secure.json` (see `secureOpts` in `js9Helper.js`).
- A page connects to the helper because `js9prefs.js` sets `helperType: "nodejs"` and
  `helperPort: 2718`. Open `js9.html` (path 1) **while the helper runs** and the page
  will find it.

Verify it's up: `pgrep -f js9Helper.js` and watch the log file.

## 4. Electron desktop app

Runs the frontend in a native window. Requires Electron installed
(`npm i -g electron`, or an `Electron.app`).

```bash
./js9 -a ~/data/m13.fits                       # open the app and load an image
./js9 -a foo.fits --colormap heat --scale log  # with display options
./js9 -a --hostfs true foo.fits                # allow host file-system access
./js9 -a --webpage ~/myjs9.html foo.fits       # use your own page in the app
```

The `js9` script (generated by `build/mkjs9`, which bakes in `JS9_SRCDIR`) finds
Electron, starts the helper unless `--helper false`, and loads the images. On macOS,
codesign Electron once to stop repeated "allow incoming connections" prompts:
```bash
sudo codesign --force --deep --sign - /path/to/Electron.app/Contents/MacOS/Electron
```

### Scripting a running app/page (the CLI)
Once an app or browser page is running with the helper, drive the public API from the
shell:
```bash
./js9 cmap heat            # change colormap
./js9 SetScale log
./js9 regions circle       # add a region
./js9 --id myJS9 regions   # target a specific display id
./js9load chandra.fits '{"scale":"log","colormap":"red"}'
```
`./js9 help` lists available commands. `js9msg` is a curl/wget-only variant that needs
no Node. See `./js9 --help` for the full switch list (also in
[01-architecture.md](01-architecture.md)).

## 5. Full web install (production-style)

For a real site with the helper and large-file support:

```bash
./configure --with-webdir=/var/www/html/js9 \
            --with-cfitsio=/path/to/cfitsio \
            --prefix=/usr/local \
            --with-helper=nodejs
make
make install
# then, in the web dir:
cd /var/www/html/js9
node js9Helper.js 1>~/logs/js9node.log 2>&1 &
```

See [02-build.md](02-build.md) for what `make install` copies, and JS9's own install
notes in [help/install.html](../help/install.html) and
[help/helper.html](../help/helper.html).

## Quick troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Image won't load from `file://` | Serve over `http://` (`python3 -m http.server`); wasm/workers dislike `file://`. |
| Browser opens but no JS9 switches applied | Chrome was already running — quit it; `quicktest` warns about this. |
| Page can't reach the helper | Helper not started, or port mismatch — check `pgrep -f js9Helper.js` and `helperPort` in `js9prefs.js`/`js9Prefs.json` (both 2718). |
| Server analysis tasks missing | You're on path 1 (no helper). Use path 2/3. |
| Helper errors about `tmp` | `mkdir -p tmp` in the run directory. |
| `./js9` says it can't find Electron | Install Electron, or use path 1/2 instead of `-a`. |
